# Working-slice acceptance

The first delivery gate toward the full feature set is a working single-part slice, following the milestone order in `AGENTS.md`. It is **not complete** when a native primitive can be built or the addon can be imported. Assemblies and later independent engineering modules follow this initial acceptance scope; passing the bracket gate does not complete the broader project goal.

## Current state and next dependencies

1. **Bootstrap:** CMake targets, bindings, addon ZIP skeleton and build documentation exist. Runtime dependency bundling and relocatable distribution remain incomplete.
2. **Core foundation:** stable IDs, basic unit-tagged parameters, persistent sketches/features/references, versioned snapshots/migration, PlaneGCS and OCCT services exist. Feature evaluation owns cached bodies, diagnostics, last-valid displays and current-result/export guards. Extrusion/subtraction, suppression, rollback and dependency-checked reorder/deletion work through native APIs. Construction/Boolean provenance and explicit named-reference repair now exist; reference-consuming features and broader naming coverage remain pending. OndselSolver belongs to the later assembly adapter and is not required for single-part acceptance.
3. **Solid integration:** managed hosts, bulk semantic display maps, face/edge/vertex selection and GPU highlights exist. Exact B-rep rays, trimmed closest points, kernel measurements and persistent-reference capture are connected to current picks. Whole-body materials, duplication/deletion/conversion, focused guards, load and undo/redo have checks. Host-owned static viewport/render visibility, per-ViewLayer hiding, collection moves/exclusions and local view now have a presentation-only adapter. The standard-workspace event test covers all selection domains, perspective picks, GPU draws, references and command undo. Animated render visibility, interactive render-thread acceptance, interactive dragging/gizmos, broader entry-point coverage and difficult curve/screen candidate cases remain; see [selection/queries](selection-and-queries.md), [Solid integration](solid-integration.md) and [entry-point audit](solid-operation-audit.md).
4. **Parametric modeling:** native sketch solving and extrusion/subtraction/history foundations exist. Blender numeric rectangle creation, depth/named-value editing and directed parameter expressions with unit validation/cycle detection exist; full modelling tools remain pending. Add sketch interaction and parameter-bound sketch dimensions, cuts/fillets UI, history UI and handles, transactional previews and cancellation. Preserve CAD topology references or expose explicit repair diagnostics rather than silently changing the selected region.
5. **Acceptance:** pending. Create and edit a mechanical bracket entirely in Blender, including sketch constraints and parameters, additive/subtractive features and fillets. Verify save/reopen, undo/redo, earlier-feature edits, failure/blocked-dependent behavior, material/rendering behavior, and STEP round trips. Repeat representative small-mechanical, ordinary and furniture-scale workflows without relaxing the default error budget. Verify the installed package without runtime downloads or user compilation.

Each completed capability must have durable documentation and proportionate verification before integration. Native geometry checks are evidence only for the kernel-service boundary; they do not stand in for the interactive bracket workflow.
